# Build plan: agent workspace (terminal · processes · browser view)

Engineering contract for one owner requirement (2026-09-08 evening): **a button on an agent that
connects you to its Linux box, so you can see what the agent is doing, navigate the file system and
watch its browser** — the Grok-style "only Chrome, a file tree and a terminal, and the Chrome is
view-only" shape. Extends `docs/build-plan.md` and `docs/build-plan-browser-vaults.md`.
Effect everywhere, pinned versions from `docs/CHANGELOG.md`.

**Migrations: none. Do not add one.** `0001`–`0013` are taken and other sessions are editing this
repo concurrently; workspace state is entirely ephemeral (D4).

## Owner requirement (verbatim intent)

> "Since each agent has its own Linux box, could we have a button to create a virtual environment
> so we can see what's going on, what the agent's doing, how to navigate the file system. Grokbot is
> able to do that and it's a weird Linux setup where there's only Chrome, file system and a terminal.
> And even the Chrome instance you cannot use."

Framed by the owner as **exploratory**. That does not license a prototype: what ships must be
production-shaped (Effect, schemas, tests) — but the surface is deliberately small and read-mostly.

## Decisions (do not re-litigate; flag in the report if you had to deviate)

| #   | decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | why                                                                                                                                                                                                                                                                                                                                   |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | **One new `Workspace` tab** on the agent detail page (`_app.agents.$agentId.tsx`, after `Files`), with three panes: **Terminal**, **Processes**, **Browser**. `Files` stays its own tab; Workspace links to it, never duplicates it.                                                                                                                                                                                                                                                                                                        | The file tree already works; a second copy would drift.                                                                                                                                                                                                                                                                               |
| D2  | **Terminal and processes are `docker` only; the browser is not** (revised 2026-09-08). A PTY on `local` is an unsandboxed shell on the owner's own machine, so `MachineProvider.openPty` still fails there with `MachineUnavailable` and the tab shows an explainer where the Terminal pane would be. The Browser pane stays: what a viewer drives is a headless Chromium Taut starts on the agent's own profile, not the host. `local` opens the same socket with `pty=0`, and `MachineInfo` carries `terminal` and `liveView` separately. | The sandbox _is_ the container; without it the feature is a remote shell on the host.                                                                                                                                                                                                                                                 |
| D3  | **Authz = whoever may manage the agent** (admin + that agent's department head) — the same gate as the vault and `grantFile`. Reuse the existing guard; do not invent a new role.                                                                                                                                                                                                                                                                                                                                                           | A PTY in the box is total access to that agent's home, vault-injected env and browser profile.                                                                                                                                                                                                                                        |
| D4  | **No migration, no new table.** Sessions are ephemeral and live in server memory. Audit goes to the logger (D10).                                                                                                                                                                                                                                                                                                                                                                                                                           | Append-only migration numbers are contended by two parallel builds.                                                                                                                                                                                                                                                                   |
| D5  | **Machine control, three REST endpoints** on the existing `agents` group (`packages/contract/src/api/agents.ts`, after the `files` block): `GET /:agentId/machine` → `MachineInfo`; `POST /:agentId/machine/start` → `MachineInfo` (ensure+start, idempotent); `POST /:agentId/machine/stop` → `MachineInfo`.                                                                                                                                                                                                                               | The Connect button must know `status` before it opens a socket, and must be able to wake a `stopped` box.                                                                                                                                                                                                                             |
| D6  | **Terminal rides a second WebSocket path, `/ws/terminal?agentId=…`** — _not_ multiplexed into `/ws`. Reuse `WsAuthenticator` from `apps/server/src/auth/wsAuthenticator.ts`.                                                                                                                                                                                                                                                                                                                                                                | `/ws` has a 64 KB payload cap, a typing-drop heuristic and a slow-client close policy tuned for events; PTY traffic would trip all three.                                                                                                                                                                                             |
| D7  | **Frames are JSON, `Schema`-validated, in a new `packages/contract/src/terminal.ts`.** client→server: `{_tag:'stdin',data}` · `{_tag:'resize',cols,rows}` · `{_tag:'input',event}` (D12, mouse/key/wheel) · `{_tag:'control',hold:boolean}`. server→client: `{_tag:'ready',shell,machineId}` · `{_tag:'data',data}` · `{_tag:'exit',exitCode}` · `{_tag:'error',message}` · `{_tag:'frame',data,width,height}` (D11) · `{_tag:'control',holder}`. **`data` is base64.**                                                                     | A PTY emits raw bytes; a UTF-8 multi-byte sequence split across two chunks corrupts if sent as a text field.                                                                                                                                                                                                                          |
| D8  | **New seam method `Machine.openPty(opts): Effect<Pty, MachineUnavailable \| ExecFailed>`** where `Pty = { write(bytes), resize(cols,rows), output: Stream<Uint8Array>, exit: Effect<number>, kill() }`, scoped so interrupting the fiber kills the child. Docker impl: `container.exec({ Cmd:['/bin/bash','-l'], Tty:true, AttachStdin:true, User:'1000:1000', WorkingDir:'/home/agent', Env:['TERM=xterm-256color', …] })` + `exec.resize({ h, w })`. **No `node-pty`** — docker's own TTY is the PTY; a native dep is not worth it.       | Same hijacked-socket plumbing as `spawnExec`; with `Tty:true` there is no stdout/stderr demux, so **do not** call `demuxStream`.                                                                                                                                                                                                      |
| D9  | **The image sets `TERM=dumb`** (`agent.Dockerfile`) for the runtimes' benefit. The PTY exec **must** override `TERM=xterm-256color` per-exec.                                                                                                                                                                                                                                                                                                                                                                                               | Otherwise the shell renders without colour or cursor addressing and xterm.js looks broken.                                                                                                                                                                                                                                            |
| D10 | **Limits, enforced server-side**: one PTY per (agent, viewer); max **4** per agent; **15 min** idle → close with a visible notice; hard cap **2 h**; output throttled to **1 MB/s** per socket, excess dropped with a single `[output truncated]` marker. Open/close/kill each `Effect.logInfo` with `{ agentId, viewerId, sessionId }`. A system message in the agent's channel is out of scope (`// TODO(plan)`).                                                                                                                         | A `yes` loop or a `cat /dev/urandom` must not be able to take the server down, and shell access must leave a trace.                                                                                                                                                                                                                   |
| D11 | **Browser live view is in this phase, and it is interactive** (owner decision, 2026-09-08 evening, overruling the earlier deferral). Taut launches Chromium in the box itself with `--remote-debugging-port`, and passes `--cdp-endpoint http://<addr>:<port>` to `playwright-mcp` instead of letting it launch its own browser. The server attaches CDP and relays `Page.startScreencast` (JPEG, **8 fps**, quality 60, max width 1280) as `{_tag:'frame'}` on the terminal socket.                                                        | The owner needs to watch what the agent browses, and to be able to log a site in by hand.                                                                                                                                                                                                                                             |
| D12 | **Take control**: a toggle in the Browser pane. While a viewer holds control, their clicks/keys/scroll/wheel go to the page as `Input.dispatchMouseEvent` / `Input.dispatchKeyEvent` CDP commands. Off by default; **no `Input.*` command is ever sent while it is off.** The pane keeps the D11 screencast running throughout, and shows a persistent `you are driving` banner. Logins land in the agent's persistent profile (`<home>/.taut/browser/profile`), which is the point: it solves 2FA and first-login for the agent.           | Grok is view-only; the owner explicitly wants more. The persistent profile makes a hand-done login stick for every later task.                                                                                                                                                                                                        |
| D13 | **Processes pane**: `GET /:agentId/machine/processes` → `ReadonlyArray<ProcessEntry>`, from `ps -eo pid,ppid,etimes,pcpu,pmem,args --no-headers` via `Machine.exec` (`procps` is already in the image), parsed and validated server-side. Poll every **3 s** only while the pane is visible. **No kill button** (`// TODO(plan)`).                                                                                                                                                                                                          | This is the "what is the agent doing right now" answer. Killing a runtime mid-task would corrupt the task and its handover.                                                                                                                                                                                                           |
| D14 | **Terminal UI = `@xterm/xterm` + `@xterm/addon-fit`**, pinned exactly, recorded in `docs/CHANGELOG.md` with every other pinned version. Lazy-loaded so the agent page's bundle is unchanged for people who never open the tab.                                                                                                                                                                                                                                                                                                              | Standard, no bundle cost by default.                                                                                                                                                                                                                                                                                                  |
| D15 | **Mutual exclusion.** The agent's Playwright and a human's clicks must never drive the same page at once. Take control is permitted only when the agent has **no running task**; if one is running the button reads **"Pause agent & take control"** and, on confirm, `SIGSTOP`s the runtime process group inside the container (mirror the `killScript` / `TAUT_EXEC_ID` targeting already in `docker.ts`), `SIGCONT`ing it when control is released. Releasing control is also automatic on disconnect and on the D10 idle timeout.       | Taut cannot gate `playwright-mcp` tool calls — it is a _separate_ stdio MCP server inside the machine (`build-plan-browser-vaults.md` D1), not proxied through `taut`. Stopping the process is the only real lock. If `SIGSTOP`/`SIGCONT` proves unreliable, fall back to disabling take-control while a task runs and **report it**. |
| D16 | **Live view rides the existing `browserAccess` flag** (`contract/src/api/agents.ts:23`), not a new one. No `browserAccess` → the Browser pane says so and offers the toggle to whoever may manage the agent.                                                                                                                                                                                                                                                                                                                                | One switch for "this agent has a browser", not two.                                                                                                                                                                                                                                                                                   |
| D17 | **Never log, persist or emit input frames.** `{_tag:'input'}` frames and anything typed while driving are excluded from every log line, trace and error payload. The screencast is not recorded to disk.                                                                                                                                                                                                                                                                                                                                    | The owner will type real passwords into this pane.                                                                                                                                                                                                                                                                                    |
| D18 | **The debug port is never published to the host.** Bind it to the container's address on `taut-<slug>` and reach it from the server over that network. Do not use `-p`, and do not bind `0.0.0.0` on a network the host can route to.                                                                                                                                                                                                                                                                                                       | An open CDP port is a full remote-control channel into the agent's box, profile and cookies.                                                                                                                                                                                                                                          |

## Blocking risk — resolve this first, it is no longer deferrable

The server must speak CDP to Chromium **inside** the agent container. The server has the docker
socket, so `docker inspect` yields the container's IP on `taut-<slug>`. Resolve, in this order, and
report which one you used and why:

**(a) Preferred** — bind the debug port to the container's `taut-<slug>` address and attach the
server to that network. **(b)** Relay through `docker exec` — needs a relay binary; `socat` is _not_
in the image today, so this costs an `agent.Dockerfile` change. **(c)** Anything else you can prove
is safe. Publishing the port to the host is not an option (D18).

Settle this **before** writing the screencast code — it decides where the CDP client lives. If none
of the options works, stop and report rather than weakening D18.

## Build order

1. **1a** — `Machine.openPty` on the seam + docker impl + `local` failure; tests.
2. **1b** — `MachineInfo`/`ProcessEntry` schemas, the four REST endpoints (D5, D13), authz (D3).
3. **1c** — `/ws/terminal` with the D7 frames and every D10 limit, plus its tests.
4. **1d** — the `Workspace` tab: Connect button, xterm.js pane, Processes table.
5. **1e** — resolve the blocking risk above, then the CDP launch change + screencast (D11, D16, D18).
   The default no-live-view path must stay byte-identical for agents without `browserAccess`.
6. **1f** — take control (D12, D15, D17), off by default, with the pause/resume interlock.

Ship 1a–1d verified before starting 1e. Land 1e before 1f — a screencast you cannot see is not
something you can debug clicks against.
